Documentação

Como usar o GlobalTime

A documentação está disponível em português e inglês; abaixo, a versão em inglês.

Visão geral

O GlobalTime mostra a hora certa no seu fuso, sincronizada com o servidor, e reúne ferramentas de tempo: relógio mundial, conversor de fusos, relógio em tela cheia, cronômetro, temporizador, Pomodoro, despertador, contagem regressiva, calendário com eventos pessoais, feriados do Brasil, nascer e pôr do sol, calculadoras de datas e conversor de timestamp Unix.

Tudo funciona no navegador, de graça e sem anúncios. Criar uma conta é opcional e serve só para guardar os seus eventos do calendário no servidor (veja Eventos e conta).

Idioma e fuso horário

Idioma

Na primeira visita, o idioma acompanha a região do seu aparelho (a localidade informada por Intl) e, depois, as preferências do navegador (navigator.languages, ou navigator.language): vale o primeiro idioma que o GlobalTime oferece. Sem nenhum compatível, a interface abre em português do Brasil.

Idiomas disponíveis: português do Brasil, português europeu, inglês, espanhol, francês, alemão, italiano, holandês, russo, japonês, chinês simplificado, coreano e árabe (da direita para a esquerda). Para trocar, use o seletor de idioma no rodapé; a escolha fica salva neste navegador e passa a valer em todas as visitas.

Nomes de feriados e datas comemorativas brasileiras ficam em português, por serem nomes próprios. Esta documentação existe em português e inglês.

Fuso horário

A hora da página inicial é exibida no fuso configurado no seu aparelho, lido com Intl.DateTimeFormat().resolvedOptions().timeZone. O GlobalTime não pede a sua localização para isso — e o fuso do aparelho não indica, por si, onde você está.

Para escolher outro, clique no nome do lugar acima do relógio. A escolha fica salva; selecione “Automático” para voltar ao fuso do aparelho. Quando o fuso exibido tem outra hora, o horário de Brasília aparece logo abaixo da data.

Trocar o fuso só muda a forma de exibir: o instante continua vindo do relógio sincronizado com o servidor. O relógio mundial, o conversor, o despertador e a contagem regressiva começam pelo fuso escolhido.

Como a sincronização funciona

O relógio do seu computador ou celular pode estar adiantado ou atrasado. Por isso o GlobalTime compara o seu relógio com o do servidor:

  1. O navegador consulta /api/hora, que devolve o horário do servidor em milissegundos, com cabeçalhos que proíbem cache.
  2. O envio e o recebimento são medidos com performance.now(), que não muda quando alguém ajusta o relógio do sistema.
  3. Supomos que o servidor leu o relógio no meio da viagem: na chegada, a hora do servidor é o valor recebido mais metade do tempo de ida e volta.
  4. Ao abrir a página são feitas até cinco medições; usamos a de menor latência, a menos afetada por filas na rede.
  5. Entre sincronizações, a hora avança com performance.now() a partir dessa medição.
  6. A cada 10 minutos há uma nova rodada (três medições), e também quando a aba volta a ficar visível depois de mais de um minuto, quando a conexão volta e quando a página é restaurada do histórico.
  7. A cada 5 segundos o avanço do cronômetro interno é comparado com o do relógio do sistema; se divergirem mais de 2 segundos (suspensão, ajuste de relógio), a sincronização é refeita na hora.
  8. Cada consulta tem limite de 5 segundos, e respostas atrasadas nunca sobrescrevem uma medição mais nova.

Se o servidor de horário falhar

  1. Servidor do GlobalTime (/api/hora), com resolução de milissegundos.
  2. Cabeçalho HTTP Date de um arquivo do próprio site: resolução de 1 segundo; o servidor é tentado de novo a cada minuto.
  3. Relógio do seu aparelho, sem correção, se nada responder. Se uma sincronização anterior deu certo, o relógio continua corrigido por ela.

Precisão e estados do relógio

Na página inicial, o estado aparece discreto no canto superior direito do relógio. Clique nele para ver a janela Precisão do relógio: fonte usada, latência, diferença do seu relógio e incerteza estimada — metade do tempo de ida e volta, o maior erro que a rede pode ter causado supondo que o servidor esteja certo.

Ela não é uma garantia de precisão absoluta: o relógio do servidor (Vercel) é mantido por NTP e não é uma fonte oficial de hora atômica; a estimativa supõe ida e volta com a mesma duração; e a tela só muda quando o navegador desenha um novo quadro. Diferenças de até 0,1 s aparecem como “em dia”.

Fusos horários

Os horários de outras cidades são calculados com a base oficial de fusos (IANA) embutida no navegador, pela API Intl.DateTimeFormat — nunca somando horas fixas —, então as regras de horário de verão de cada lugar são respeitadas. O Brasil não adota horário de verão desde 2019.

  • Relógio mundial: começa com poucas cidades a partir do seu fuso; adicione, reordene e remova cidades. A lista fica salva neste navegador.
  • Conversor: converte um horário entre cidades ou fusos IANA, avisa horários inexistentes ou repetidos na troca do horário de verão e tem um planejador de reuniões.
  • Tela cheia: relógio grande para TVs e monitores, com fusos extras; os ajustes ficam no endereço da página.

Cronômetro

Mede o tempo com performance.now() durante a sessão, então não é afetado por ajustes do relógio do sistema. Registre voltas com L; a lista mostra o tempo de cada volta, a diferença para a anterior, o total e destaca a melhor e a pior. Ela tem rolagem própria, para não esticar a página.

Copie os resultados ou exporte um CSV (separador ;, com colunas em milissegundos exatos). Se a página for recarregada, o cronômetro continua de onde estava.

Temporizador e Pomodoro

A contagem é calculada a partir do instante final, não subtraindo segundos: o tempo restante continua certo mesmo se o navegador atrasar a aba em segundo plano. Ao terminar, toca o som escolhido (até 5 minutos, se “Repetir” estiver ligado) e, se você permitiu, aparece uma notificação do sistema. Se a página estava fechada, ela informa quando o tempo acabou.

O Pomodoro alterna foco, pausa curta e pausa longa com durações ajustáveis e guarda o histórico do dia neste navegador. Som, notificações e “manter a tela ligada” ficam em seções recolhíveis.

Despertador e contagem regressiva

Os alarmes usam o horário sincronizado e podem ter data, repetição semanal, fuso e som. Eles só tocam com a página aberta: com a aba ou o navegador fechados, nada toca, e celulares podem suspender abas em segundo plano. Para compromissos importantes, use também o despertador do aparelho.

A contagem regressiva mostra quanto falta para uma data em qualquer fuso e gera um link para compartilhar. As contagens salvas aparecem no calendário.

Calculadoras, timestamp e sol

  • Calculadoras: diferença entre datas (com dias úteis descontando feriados nacionais e, se escolhidos, estaduais), soma de dias corridos ou úteis, duração entre horários e conversão de unidades.
  • Timestamp Unix: converte segundos ou milissegundos em datas (ISO 8601, UTC e no fuso escolhido) e o caminho inverso.
  • Nascer e pôr do sol: cálculo pelo algoritmo da NOAA para cidades ou coordenadas. A localização só é pedida se você clicar em “Usar minha localização”, e as coordenadas não saem do navegador.

Calendário

O calendário abre no ano inteiro, com os 12 meses em grade. Use os botões Ano, Mês e Semana para trocar a visualização; a data selecionada é mantida. As setas avançam ou voltam um período e “Hoje” volta ao período atual. Clique no nome de um mês para abri-lo.

Feriados nacionais, estaduais e da capital escolhida, pontos facultativos, datas comemorativas, as suas contagens e os seus eventos aparecem em todas as visualizações. O painel ao lado mostra os detalhes do dia selecionado.

Eventos e conta

Crie eventos com título, data, horário e descrição opcionais e a opção “Repetir todo ano”, para aniversários (29 de fevereiro aparece em 28 de fevereiro nos anos não bissextos). Edite ou exclua pelo painel do dia; dois cliques num dia (ou Enter) criam um evento nele.

Sem conta

Os eventos ficam só neste navegador (armazenamento local). Apagar os dados do site os remove.

Com conta

Com e-mail e senha, os eventos ficam no servidor e aparecem em qualquer aparelho em que você entrar. Ao entrar, o GlobalTime oferece levar para a conta os eventos que estavam só no navegador.

  • A senha é guardada com scrypt e sal aleatório; o servidor nunca guarda a senha em si.
  • A sessão usa um cookie HttpOnly, SameSite=Lax e Secure, válido por 30 dias.
  • Tentativas de entrar são limitadas, e cada conta só acessa os próprios eventos.
  • Ainda não há recuperação de senha por e-mail. Você pode excluir a conta e todos os eventos a qualquer momento, confirmando a senha.

Dados de feriados

Os dados foram compilados em 19/10/2026 a partir de leis e calendários oficiais; cada data traz a base legal e a fonte.

  • Nacionais: Lei nº 662/1949 (redação da Lei nº 10.607/2002), Lei nº 6.802/1980 e Lei nº 14.759/2023 (20 de novembro, nacional desde 2024).
  • Pontos facultativos não são feriados: valem para a administração pública federal (em 2026, Portaria MGI nº 11.460/2025).
  • Datas móveis (Carnaval, Sexta-feira Santa, Páscoa, Corpus Christi) são calculadas a partir da Páscoa.
  • Estaduais: verificados para 24 unidades da federação; MG, MT e PR não têm feriado estadual próprio.
  • Municipais: apenas 21 capitais com lei localizada. Confirme com a prefeitura da sua cidade.

Uso sem internet

O GlobalTime é um aplicativo web instalável (PWA). Depois da primeira visita, páginas, estilos, fontes, traduções e scripts ficam guardados, e as ferramentas que não dependem da rede funcionam offline.

A sincronização precisa de internet e nunca vai para o cache — um horário guardado seria um horário errado. As contas e os eventos guardados na conta também precisam de conexão. Quando há uma nova versão, aparece o aviso “Atualizar”.

Permissões do navegador

  • Som: só é liberado depois de uma interação, por isso é preparado quando você clica em Iniciar.
  • Notificações: pedidas só quando você clica em Ativar.
  • Manter a tela ligada: disponível em parte dos navegadores; solto quando a aba fica oculta e pedido de novo quando ela volta.
  • Tela cheia: só por clique ou tecla; Esc sai.
  • Localização: usada apenas no nascer e pôr do sol, e só se você pedir.

Privacidade

  • Sem anúncios, rastreadores ou análise de audiência. Fontes e ícones vêm do próprio site.
  • Preferências (idioma, tema, fuso), cronômetros, alarmes, cidades, históricos e eventos sem conta ficam no localStorage do navegador.
  • Com conta, o servidor guarda apenas o e-mail, a senha protegida e os seus eventos.
  • A consulta de horário não envia dados pessoais nem cookies.

Estrutura do projeto

Site estático em HTML, CSS e JavaScript puro, sem etapa de build nem dependências em produção, com Vercel Functions em api/.

  • *.html — páginas; cabeçalho, rodapé e metadados são mantidos por dev/gerar.mjs a partir de dev/site.mjs.
  • scripts/nucleo/ — lógica sem DOM (tempo, sincronização, calendário, eventos) e componentes.
  • scripts/paginas/ — um script por página. scripts/i18n/ — idiomas e traduções.
  • api/hora.js, api/conta.js, api/eventos.js — funções; auxiliares em api/_lib/.
  • sw.js — service worker (pré-cache gerado).

Executar e testar

Requer Node.js 20 ou superior; não há pacotes para instalar.

npm run dev              # http://localhost:3000
npm run gerar            # atualiza cabeçalho, rodapé, textos, sitemap e service worker
npm run checar           # falha se algo estiver desatualizado
npm test                 # testes de unidade e das funções
npm run test:navegador   # todas as páginas no Chrome/Edge (desktop e celular)
npm run test:pwa         # service worker e uso offline

No servidor local, as contas usam um armazenamento em memória (apagado ao reiniciar). Opções dos testes de navegador: SO=/cronometro (uma página), FUSO=Asia/Tokyo, TEMA=dark e INTEIRA=1 (captura da página inteira).

Implantação na Vercel

O projeto é publicado na Vercel como está. As contas de usuário precisam de um banco Redis: crie um Upstash Redis pelo Marketplace da Vercel (há plano gratuito) e conecte-o ao projeto. A Vercel cria as variáveis: 

KV_REST_API_URL=…
KV_REST_API_TOKEN=…

Os nomes UPSTASH_REDIS_REST_URL e UPSTASH_REDIS_REST_TOKEN também são aceitos. Sem essas variáveis o site funciona normalmente e os eventos ficam só no navegador. Defina SITE_URL ao rodar npm run gerar para o endereço público usado no sitemap.

API

GET /api/hora

Devolve o horário do servidor em milissegundos, sem cache.

curl https://SEU-DOMINIO/api/hora
# {"timestamp":1792519155792}

/api/conta

GET informa se as contas estão disponíveis e qual conta está conectada. POST com acao igual a cadastrar, entrar ou sair; DELETE com a senha exclui a conta. Pedidos que mudam dados precisam de JSON e da mesma origem. 

await fetch("/api/conta", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ acao: "entrar", email: "voce@exemplo.com", senha: "…" }),
});

/api/eventos

Com sessão aberta: GET lista, POST cria, PUT ?id= atualiza e DELETE ?id= exclui. Campos: titulo, data (AAAA-MM-DD), hora (HH:MM, opcional), descricao e anual. 

await fetch("/api/eventos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ titulo: "Aniversário", data: "2026-03-14", anual: true }),
});

Traduções

Os textos ficam em scripts/i18n/textos/: pt-BR.js é a referência, e cada idioma tem um arquivo com as mesmas chaves (os testes conferem). No HTML, elementos com data-i18n são preenchidos em português pelo gerador e traduzidos no navegador; nos scripts, use t("chave", { parametros }). Para incluir um idioma, adicione-o em scripts/i18n/idiomas.js e crie o arquivo de textos.

Overview

GlobalTime shows the exact time in your time zone, synchronized with the server, and brings together time tools: world clock, time zone converter, full-screen clock, stopwatch, timer, Pomodoro, alarm clock, countdown, calendar with personal events, Brazilian holidays, sunrise and sunset, date calculators and a Unix timestamp converter.

Everything runs in the browser, free and without ads. Creating an account is optional and only serves to store your calendar events on the server (see Events and account).

Language and time zone

Language

On your first visit, the language follows your device's region (the locale reported by Intl) and then your browser preferences (navigator.languages, or navigator.language): the first language GlobalTime offers wins. If none match, the interface opens in Brazilian Portuguese.

Available languages: Brazilian Portuguese, European Portuguese, English, Spanish, French, German, Italian, Dutch, Russian, Japanese, Simplified Chinese, Korean and Arabic (right to left). To switch, use the language selector in the footer; your choice is saved in this browser and applies on every visit.

Names of Brazilian holidays and observances stay in Portuguese, since they are proper names. This documentation is available in Portuguese and English.

Time zone

The time on the home page is shown in the time zone configured on your device, read with Intl.DateTimeFormat().resolvedOptions().timeZone. GlobalTime does not ask for your location to do this — and your device's time zone does not, by itself, reveal where you are.

To choose a different one, click the place name above the clock. Your choice is saved; select “Automatic” to go back to the device's time zone. When the displayed time zone has a different time, Brasília time appears just below the date.

Changing the time zone only changes how the time is displayed: the instant still comes from the clock synchronized with the server. The world clock, converter, alarm clock and countdown start from the chosen time zone.

How synchronization works

Your computer's or phone's clock may be running fast or slow. That's why GlobalTime compares your clock with the server's:

  1. The browser queries /api/hora, which returns the server time in milliseconds, with headers that forbid caching.
  2. Sending and receiving are measured with performance.now(), which doesn't change when someone adjusts the system clock.
  3. We assume the server read its clock halfway through the round trip: on arrival, the server time is the received value plus half the round-trip time.
  4. When the page opens, up to five measurements are taken; we use the one with the lowest latency, which is the least affected by network queuing.
  5. Between synchronizations, the time advances with performance.now() from that measurement.
  6. Every 10 minutes there is a new round (three measurements), and also when the tab becomes visible again after more than a minute, when the connection comes back and when the page is restored from history.
  7. Every 5 seconds, the progress of the internal timer is compared with that of the system clock; if they diverge by more than 2 seconds (sleep, clock adjustment), synchronization is redone immediately.
  8. Each query has a 5-second limit, and late responses never overwrite a newer measurement.

If the time server fails

  1. GlobalTime server (/api/hora), with millisecond resolution.
  2. HTTP Date header from a file on the site itself: 1-second resolution; the server is retried every minute.
  3. Your device's clock, uncorrected, if nothing responds. If a previous synchronization succeeded, the clock stays corrected by it.

Accuracy and clock states

On the home page, the state appears discreetly in the top-right corner of the clock. Click it to open the Clock accuracy dialog: source used, latency, how far off your clock is and the estimated uncertainty — half the round-trip time, the largest error the network could have caused assuming the server is correct.

It is not a guarantee of absolute accuracy: the server clock (Vercel) is kept by NTP and is not an official atomic time source; the estimate assumes both legs of the round trip take the same time; and the screen only changes when the browser draws a new frame. Differences of up to 0.1 s are shown as “accurate”.

Time zones

Times in other cities are calculated with the official time zone database (IANA) built into the browser, through the Intl.DateTimeFormat API — never by adding fixed hours —, so each place's daylight saving time rules are respected. Brazil has not observed daylight saving time since 2019.

  • World clock: starts with a few cities based on your time zone; add, reorder and remove cities. The list is saved in this browser.
  • Converter: converts a time between cities or IANA time zones, warns about nonexistent or repeated times at daylight saving transitions and includes a meeting planner.
  • Full screen: a large clock for TVs and monitors, with extra time zones; the settings are kept in the page address.

Stopwatch

Measures time with performance.now() during the session, so it is not affected by system clock adjustments. Record laps with L; the list shows each lap's time, the difference from the previous one and the total, and highlights the best and worst. It scrolls on its own, so it doesn't stretch the page.

Copy the results or export a CSV (; separator, with columns in exact milliseconds). If the page is reloaded, the stopwatch continues where it left off.

Timer and Pomodoro

The countdown is calculated from the end instant, not by subtracting seconds: the remaining time stays correct even if the browser throttles the tab in the background. When it ends, the chosen sound plays (for up to 5 minutes if “Repeat” is on) and, if you allowed it, a system notification appears. If the page was closed, it tells you when the time ran out.

The Pomodoro alternates focus, short break and long break with adjustable durations and keeps the day's history in this browser. Sound, notifications and “keep the screen on” are in collapsible sections.

Alarm clock and countdown

Alarms use the synchronized time and can have a date, weekly repetition, time zone and sound. They only ring while the page is open: with the tab or browser closed, nothing rings, and phones may suspend background tabs. For important appointments, also use your device's alarm clock.

The countdown shows how much time is left until a date in any time zone and generates a link to share. Saved countdowns appear in the calendar.

Calculators, timestamp and sun

  • Calculators: difference between dates (with business days excluding national holidays and, if selected, state holidays), adding calendar or business days, duration between times and unit conversion.
  • Unix timestamp: converts seconds or milliseconds into dates (ISO 8601, UTC and in the chosen time zone) and the other way around.
  • Sunrise and sunset: calculated with the NOAA algorithm for cities or coordinates. Your location is only requested if you click “Use my location”, and the coordinates never leave the browser.

Calendar

The calendar opens on the whole year, with the 12 months in a grid. Use the Year, Month and Week buttons to switch views; the selected date is kept. The arrows move forward or back one period and “Today” returns to the current period. Click a month's name to open it.

National, state and selected-capital holidays, optional federal holidays (pontos facultativos), observances, your countdowns and your events appear in every view. The side panel shows the details of the selected day.

Events and account

Create events with a title, date, optional time and description, and the “Repeat every year” option, for birthdays (February 29 appears on February 28 in non-leap years). Edit or delete them from the day panel; double-clicking a day (or pressing Enter) creates an event on it.

Without an account

Events are stored only in this browser (local storage). Clearing the site's data removes them.

With an account

With an email and password, events are stored on the server and appear on any device you sign in on. When you sign in, GlobalTime offers to move the events that were only in the browser to your account.

  • The password is stored with scrypt and a random salt; the server never stores the password itself.
  • The session uses an HttpOnly, SameSite=Lax and Secure cookie, valid for 30 days.
  • Sign-in attempts are rate-limited, and each account can only access its own events.
  • There is no password recovery by email yet. You can delete your account and all its events at any time by confirming your password.

Holiday data

The data was compiled on October 19, 2026 from official laws and calendars; each date includes its legal basis and source.

  • National: Brazilian Law nº 662/1949 (as amended by Lei nº 10.607/2002), Brazilian Law nº 6.802/1980 and Brazilian Law nº 14.759/2023 (November 20, a national holiday since 2024).
  • Optional federal holidays (pontos facultativos) are not holidays: they apply to the federal public administration (in 2026, Portaria MGI nº 11.460/2025).
  • Movable dates (Carnaval, Sexta-feira Santa, Páscoa, Corpus Christi) are calculated from Easter.
  • State: verified for 24 Brazilian states/federal units; MG, MT and PR have no state holiday of their own.
  • Municipal: only 21 state capitals with a law located. Check with your city hall.

Using it offline

GlobalTime is an installable web app (PWA). After the first visit, pages, styles, fonts, translations and scripts are stored, and the tools that don't depend on the network work offline.

Synchronization requires internet and is never cached — a stored time would be a wrong time. Accounts and events stored in an account also require a connection. When a new version is available, the “Update” notice appears.

Browser permissions

  • Sound: only allowed after an interaction, so it is prepared when you click Start.
  • Notifications: requested only when you click Enable.
  • Keep the screen on: available in some browsers; released when the tab is hidden and requested again when it returns.
  • Full screen: only by click or key press; Esc exits.
  • Location: used only for sunrise and sunset, and only if you ask.

Privacy

  • No ads, trackers or audience analytics. Fonts and icons are served from the site itself.
  • Preferences (language, theme, time zone), stopwatches, alarms, cities, history and events without an account are kept in the browser's localStorage.
  • With an account, the server stores only your email, your protected password and your events.
  • The time query sends no personal data or cookies.

Project structure

A static site in plain HTML, CSS and JavaScript, with no build step and no production dependencies, plus Vercel Functions in api/.

  • *.html — pages; header, footer and metadata are maintained by dev/gerar.mjs from dev/site.mjs.
  • scripts/nucleo/ — DOM-free logic (time, synchronization, calendar, events) and components.
  • scripts/paginas/ — one script per page. scripts/i18n/ — languages and translations.
  • api/hora.js, api/conta.js, api/eventos.js — functions; helpers in api/_lib/.
  • sw.js — service worker (generated precache).

Running and testing

Requires Node.js 20 or later; there are no packages to install.

npm run dev              # http://localhost:3000
npm run gerar            # updates header, footer, texts, sitemap and service worker
npm run checar           # fails if anything is out of date
npm test                 # unit and function tests
npm run test:navegador   # all pages in Chrome/Edge (desktop and mobile)
npm run test:pwa         # service worker and offline use

On the local server, accounts use in-memory storage (cleared on restart). Browser test options: SO=/cronometro (a single page), FUSO=Asia/Tokyo, TEMA=dark and INTEIRA=1 (full-page screenshot).

Deploying to Vercel

The project is deployed to Vercel as is. User accounts require a Redis database: create an Upstash Redis database from the Vercel Marketplace (there is a free plan) and connect it to the project. Vercel creates the variables: 

KV_REST_API_URL=…
KV_REST_API_TOKEN=…

The names UPSTASH_REDIS_REST_URL and UPSTASH_REDIS_REST_TOKEN are also accepted. Without these variables the site works normally and events stay only in the browser. Set SITE_URL when running npm run gerar to the public address used in the sitemap.

API

GET /api/hora

Returns the server time in milliseconds, uncached.

curl https://YOUR-DOMAIN/api/hora
# {"timestamp":1792519155792}

/api/conta

GET reports whether accounts are available and which account is signed in. POST with acao set to cadastrar, entrar or sair; DELETE with the password deletes the account. Requests that change data require JSON and the same origin. 

await fetch("/api/conta", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ acao: "entrar", email: "you@example.com", senha: "…" }),
});

/api/eventos

With an active session: GET lists, POST creates, PUT ?id= updates and DELETE ?id= deletes. Fields: titulo, data (AAAA-MM-DD), hora (HH:MM, optional), descricao and anual. 

await fetch("/api/eventos", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ titulo: "Birthday", data: "2026-03-14", anual: true }),
});

Translations

Texts live in scripts/i18n/textos/: pt-BR.js is the reference, and each language has a file with the same keys (the tests check this). In the HTML, elements with data-i18n are filled in Portuguese by the generator and translated in the browser; in scripts, use t("chave", { parametros }). To add a language, add it to scripts/i18n/idiomas.js and create its texts file.
